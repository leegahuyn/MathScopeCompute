# N6 원본 의무 후속 검증

기존 PR #30의 `a35bb0727953e56470682839c98fd9759306d18c`에서 이어가는 추가 전용 검증이다. 원본 producer, 수식, acceptance 기준, main, 별도 Picard PR #31 및 공개 웹사이트를 수정하지 않는다.

첨부 패키지의 24개 파일 해시와 길이를 재검증했다. ZIP SHA-256은 `0c448b5171e1feeb41cb08b24acf56e8f038b40f6064105f3146298ce92d519f`이다. 첨부 패키지의 이전 로컬 실행 기록은 새 클라우드 실행의 성공 증거가 아니다.

## 실제 수정

기존 검증기는 압축 원본의 전체 해시를 검사하면서도 별도 `header.json`에서 함수 registry를 읽었다. 새 진입점은 압축 내부의 헤더와 별도 헤더를 엄격하게 대조한 다음에만 기존 Stage4를 실행한다. 후속 함수 감사는 압축 내부에서 읽은 헤더를 사용한다. 전체 3,892,594개 노드의 기존 해시 인증도 그대로 실행한다. 이 인증 보강 자체는 새로운 수학적 소거가 아니다.

## 수학적 판정

패키지의 주장인 원본 Guard 6개 소거를 독립적으로 검토하고 클라우드에서 재실행한다. 실제 성공 후에만 새 실행 evidence를 공식 후속 장부로 보존한다. 주장하는 적용 영역은 원래의 허용 band와 양의 반지름 annular chart이며, 축 연장이나 전체 함수 정칙성을 포함하지 않는다. 기존 상세 해석 증명은 `PROOF_KO.md`에 있다.

예상 후속 장부는 Guard 10 / Jet 230 / PDE 1,020 = 1,260이지만, 코드 게시 시점에는 새 클라우드 재실행이 아직 검증되지 않았다. `allOriginal1266Closed=false`, N6-01 OPEN, N6-02 PARTIAL, M3 56/64를 유지한다. 실제 `complete_gr` 정칙성은 조건부 압력 보조정리만으로 증명되지 않는다. 비영 잔여 다항식을 0으로 처리하지 않는다.

## 재현

`.github/workflows/m3-n6-remaining-closure.yml`이 기존 인증된 원본/prepare/prior 아티팩트를 GitHub Actions 안에서 소비한다. 전체 그래프를 재생성하거나 사용자의 노트북에 내려받지 않는다. 표준 라이브러리 헤더 변조 대조, 원본별 회귀 및 독립 SymPy 계산을 실행하고 실패 시에도 결과를 업로드한다. 모든 최종 증거는 기존 브랜치와 PR #30에 보존한다.
