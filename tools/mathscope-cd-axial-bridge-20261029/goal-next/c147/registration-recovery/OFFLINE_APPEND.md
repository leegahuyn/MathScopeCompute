GitHub run 44698543085 reached the original Repeat candidate with
22,380,596 nodes, wrote its native snapshot, then stopped before the
new indexed registrar. The failure was the Forced source hash assertion.
The filesystem has the original PR30 module with SHA-256 starting
`b41f2987`. The approved Node loader resolves that same module URL to a
reversible storage overlay with SHA-256 starting `1093de46`. The
registration adapter read the filesystem and compared it with the
effective-module hash.

`76a92cb5724a47965cba1f4f31a72baec0e82865d0916c8e0ed74572bdad8578`.
The raw file has Git blob SHA-1
`03c3e125d93a5bd9e66d00c5f237b100c7b48b50`. The harmonic
reconstruction module is already the correct unpatched filesystem
version, with SHA-256
`339c8cb4e5853ba4afe68f3b37933784241baaef3fcf655d5d88aa9f13708d20`.
The fix needs to validate the original file's role and expose the
effective verified helper under the same runtime loader before the

current, inverse or label mismatch.

## Independent typed reconstruction

The archived graph is sufficient to reconstruct the new expressions
as graph data. The checker authenticates the complete original
22,380,596-node stream and native registry. It uses the archived original
carrier `#17732747`, the ten original phase roots, and each of the
actual positive and negative Repeat velocity and pressure coefficients.
It verifies their conjugate pairs and reconstructs the complete real
sum in signed modes (\pm1,\pm2,\pm3,\pm4), retaining all four physical
components.

For each new component and sign the checker reconstructs the five
leaves in the archived Forced own wrapper. The level coordinate, the
half-integer branch bounds, zero-arm direction, native `xi/v` guards,
shell and all four original slow guards are checked separately. The
bounded body is closed over the same 16 actual local slots. The
reference wrapper copies the original reference-to-own argument tuple
and the already installed velocity or pressure scale. It changes the
typed own-body application to the new body. It leaves the physical
angle, frozen nearest copy and reference scaling in the same positions.

The new records use the same 162 rows per indexed field. Every row
retains the original label, slow-coordinate guards, local values,
coefficient and six derivative directions. The checker independently
checks each row argument's free-coordinate support and each
derivative-map coefficient's constancy in the differentiated directions.
This addresses an otherwise possible deterministic failure of the
live builder after its source hash preflight.

The output is 16 expression records, four typed field records, 648
indexed rows and 1,994 exact AST records extending the protected
archive EOF. These are **offline data**. The checker allocates its own
append IDs and does not authenticate a native runtime instance or
promise byte-for-byte agreement with the future runtime's hash-consed
append. The private live registry owner and predecessor seals cannot
be restored from the exported nodes by the repository's current
runtime. The corrected live run is still needed for the official
registration result. Neither output proves global derivative closure,
the updated whole PDE, or any of the final jets.

The two executions, one on C132 and one on the actual failed-run archive,
emit identical bytes for the appended nodes, appended definitions, and
report. The prior candidate and registry are byte-identical too. The
archived manifest differs only by its executing-commit metadata. Under
the pinned same runtime inputs, the future native source helper is
expected to realize these same typed expressions up to algebraic
normalization, expression interning and unused capture-variable IDs.
That semantic comparison can be checked once the actual native append
is available.
