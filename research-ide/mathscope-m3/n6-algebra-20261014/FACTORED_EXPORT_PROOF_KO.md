# 실제 클라우드 분모 전개 정지의 정확한 재검증

run38523108728에서 원본 PDE 0/1 성분의 실제 defining-body 전개는 조건부 분자 7,492/11,428항을 만들었다. 그러나 분모 전체를 곱해 `residual*D-N`을 계산하는 마지막 재구성 검사가 정확한 monomial/product 예산에서 멈췄다. 이 후보 수를 인증 성공으로 세지 않는다.

새 검증기는 **같은 원본 circuit과 이전 증거를 클라우드 runner에서만 재사용**한다. defining body나 389만 노드 producer를 다시 만들지 않는다. 입력 receipt/source roots/모든 원본 항과 계수의 결합을 다시 확인한 뒤 같은 별도 BigInt 유리함수 검증기를 실행한다.

원본 계수와 인수 결합을 확인하는 첫 검사도 전체 유리함수 전개를 중복하지 않는다. 별도의 exact BigInt 정규화가 각 원본 항의 `계수*product(source인수^차수)`와 저장된 term root, 그리고 그 전체 합과 저장된 residual root를 다시 비교한다. 쓰는 규칙은 덧셈·곱셈의 결합/교환법칙과 유리수 상수의 정확한 합·곱·정수 거듭제곱뿐이다. 전체 descriptor를 정확히 intern하므로 hash 충돌이나 수치 샘플을 근거로 삼지 않는다. 이것으로 원본 654항 전체를 첫 검사에서 두 번 전개하여 메모리를 소모하는 문제를 피한다. 이후 실제 전체 분자 정규화는 한 번 수행한다.

바뀐 수식은 `residual - N * product_j(P_j^(-p_j))`이다. 원래 검증기의 공통 분모를 그 정확한 인수 `P_j`와 양의 정수 차수 `p_j`로 유지한다. 각각의 음의 정수 거듭제곱은 원본 인수의 nonzero definedness를 보존한다. 전체 D 다항식을 먼저 전개하지 않으므로 같은 factored least-common denominator에서 정확한 `N-N`이 계산된다. 항 삭제나 근삿값, 새 함수 값, 새 해석적 가정으로 결과를 바꾸지 않는다.

분자 계수에 `+1`을 넣은 `residual-(N+1)*product_j(P_j^(-p_j))`가 0으로 통과하면 실패한다. ordinary/Taylor 미분 차이에 `+1`을 넣는 대조도 실행한다. 17개 독립적인 이항식 분모를 가진 테스트는 전체 분모가 131,072항으로 기존 50,000항 예산을 넘는데도, 정확한 factored 재구성과 변이 거절을 작은 계산으로 수행함을 확인한다.

새 단계는 분모 전개 방법의 계산상 낭비를 고친다. 원본 source 정의역, lazy row의 비활성 피연산자 정의, W/M/S·모멘트·Picard strip·전체 Cartesian 해석적 동일성을 증명하지 않는다. 원본 1,020항과 모든 남은 조건부 monomial을 보존하고 N6 상태 승격을 하지 않는다.
