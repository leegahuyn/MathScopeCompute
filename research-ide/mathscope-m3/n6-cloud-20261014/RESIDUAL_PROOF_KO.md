# 원본 잔여항의 정확한 함수 항등식 정규화

Stage B는 이전 175/203/690항에서 이미 증명한 `sqrt(2)^2=2`를 반복해서 새 성과로 세지 않는다. 이전 클라우드의 169/197/654항, 합계 1,020항을 입력으로 삼는다. 각 항과 실패 시도는 지우지 않고 독립적인 원본 항 번호·유리계수·원본 source ID와 함께 보존한다.

새 계산은 원본 source witness에 실제로 결합된 두 가지 함수 항등식만 사용한다.

1. 원본 `sqrt_positive(u)`가 정의되는 실수 정의역에서 `(sqrt_positive(u))^(2k+r)=u^k*(sqrt_positive(u))^r`이다. `u`의 덧셈·곱셈·비음수 정수 거듭제곱과 유리수 상수는 정확한 유리계수 다항식으로 전개한다.
2. 원본 지수함수 인수들이 유한하게 정의되는 곳에서 `product exp(a_i)^n_i = exp(sum n_i*a_i)`이다. 인수의 정확한 다항식 전개가 같을 때에만 동일한 지수함수 항으로 결합한다. 합이 정확히 0이면 `exp(0)=1`이다. 비상수 역수는 그 원본 source ID에 결합된 불투명한 실제 피연산자로 남겨서 분모를 지우지 않는다.

새 지수함수 기호는 원본 피연산자들로 만든 정확한 인수 다항식의 SHA-256에 결합한다. 모든 새 기호의 정의를 결과에 보존한다. Fourier/Picard/Volterra/급수/등록 함수의 미분은 이 항등식으로 대체하지 않는다.

독립 검증기는 계산기의 함수를 불러오지 않는다. 계산기는 지수 맵과 이진 거듭제곱을 쓰고, 검증기는 반복된 인수들의 단어와 반복 곱셈을 쓴다. 검증기는 원본 witness·registry SHA-256, 항 전수 보존, 각 제곱근과 지수함수 변환, 마지막 유리계수 합계를 다시 계산한다. 계수 변경, 항 누락, 원본 witness hash 변경, 출력 인수 삽입의 네 음성 대조를 실제로 거절해야 한다.

이전 checkpoint에 없는 피연산자는 원본 SQLite prefix의 SHA-256을 먼저 확인한 뒤 read-only 조회한다. 추가 witness를 결과에 보존한다. 외부 재검증은 `verify(..., verified_database=원본_prefix_경로)`에 같은 DB를 제공해야 한다. 독립 검증기는 DB 전체 hash와 각 추가 witness의 원본 행을 다시 비교한다. 추가 witness의 자기 hash만으로 원본 인증을 인정하지 않는다. prefix 범위 밖의 노드는 정확한 실패 이유와 원본 항을 보존한다.

이 결과는 원본 피연산자와 분모가 정의된 조건 아래의 함수 항등식 정규화다. 원본 94개 전역 guard, source image, 모든 차수 클래스, 전체 Cartesian 미분 및 Navier–Stokes PDE의 해석적 동일성은 여기서 증명되지 않는다. 항 수가 줄거나 조건부 다항식이 0이 되더라도 N6-01/N6-02 승격 사유로 쓰지 않는다. 유한 계산 예산을 넘으면 정확한 이유와 원본 항을 그대로 남긴다.
