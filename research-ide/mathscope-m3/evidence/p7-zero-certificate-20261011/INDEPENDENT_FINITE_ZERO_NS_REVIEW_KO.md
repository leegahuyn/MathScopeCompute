# P7 유한 영점 인증 독립 수학 검토 — ns_proof_audit

## 결론과 독립성

동결된 `p7/zero_certificate.py`와 `p7/ZERO_CERTIFICATE_KO.md`, 실제 두 높이의 전체 기록, 최종 12개 검사 및 관측 종료 코드 기록을 읽었다. **선언한 T=20·30 범위에서 현재 구체적인 수학적 결함을 찾지 못했다.** 전체 경로에 대한 비영·분기 인증과 실제 부호 구간의 개수 포화로 유한 높이의 임계선 결론을 도출하는 구조가 맞다.

검토자는 zero constructor의 작성자가 아니다. 다만 공유 `ball_backend.py`의 정확한 입력·외향 직렬화는 이 검토자가 작성했다. 따라서 zero 경로와 포화 논증에 대한 독립 읽기 검토이며, 공유 산술·직렬화까지 다른 구현으로 검증했다는 뜻은 아니다. 새 FLINT 함숫값 계산은 수행하지 않았고, 저장된 정확한 끝점·부등식·해시를 별도의 유리수 검사로 재확인했다. 그 기록은 [finite-zero-ns-read-audit.json](finite-zero-ns-read-audit.json)에 있다.

## 2. 전체 tube와 연속 argument

각 정확한 선분의 좌표 반길이 중 최댓값을 r라 하면 padding=r/8>0이다. 두 좌표를 모두 이만큼 넓히므로 수평·수직 선분에도 양의 이차원 근방이 생긴다. 정확한 사각형의 각 끝점을 Arb가 외향으로 감싼다는 점이 실제 저장 끝점에서도 확인된다.

`tube.contains(1)==false`이고 실제 ζ(tube)가 유한·비영이면 선분 근방에서 ζ는 정칙·비영이다. 실제 ζ(tube)/ζ(a)의 실부 전체 하한이 양수이면, 정확한 함수 ζ(s)/ζ(a)는 선분 전체에서 오른쪽 반평면에 있고 시작값은 1이다. 이 영역에는 하나의 연속 로그가 있으므로 끝점 argument의 주값이 그 선분에서의 실제 argument 증가량을 준다. 분모와 분자의 계산 오차를 독립 ball로 넓히는 것은 이 포함성을 해치지 않는다.

따라서 코드가 각 끝점 비율의 `arg()`를 더해도 branch를 임의로 접거나 숨겨진 2π를 잃지 않는다. 이는 양끝 표본이 비영이라는 조건보다 강하다. 실제 negative control은 [1/2+14i, 1/2+15i]의 양끝 ζ가 비영이어도 영점을 지나는 전체 tube를 거절한다. 극점을 포함한 tube, cell/depth/evaluation/time 예산 소진 역시 성공으로 넘어가지 않는다.

## 3. 논증 원리, 총수, 부호 구간의 포화

경로는 [-1,2]×[-T,T]의 반시계 경계다. ζ의 유일한 단순극 1은 내부에 있고 음의 짝수 자명한 영점은 외부에 있다. 그러므로 실제 감김수 W로부터 중복도를 포함한 내부 영점 총수는 W+1이다. 감김수가 정수라는 논증 원리의 전제를 먼저 확보한 뒤, 구간이 정수 하나를 포함하고 실제 폭도 1e-30 이하인지 검사하는 순서가 맞다.

다른 계산 경로에서는 연속 실함수

\[
Z(t)=\exp(i\vartheta(t))\zeta(1/2+it),\qquad
\vartheta(t)=\operatorname{Im}\log\Gamma(1/4+it/2)-\tfrac t2\log\pi
\]

의 실제 양끝 부호를 확인한다. Γ 인자의 실부는 1/4이므로 코드의 analytic log-Gamma branch가 안전하다. Z의 실성은 표준 함수 항등식에 근거하며, 계산한 허수 구간에 0이 들어간다는 검사만으로 새로 증명한 것은 아니다. [DLMF 25.10.1–2](https://dlmf.nist.gov/25.10)에서 이 함수와 부호 변화에 의한 영점 분리를 직접 확인했다.

서로 겹치지 않는 k개의 양의 부호 구간은 적어도 k개의 영점을, 켤레 대칭은 음의 높이에 k개를 더 보장한다. **W+1=2k**를 확인한 뒤에야 각 구간의 유일성·단순성과 나머지 영점 부재를 결론낸다. 따라서 별도의 미검증된 실수축 무영점 가정을 넣어 총수를 반으로 나누는 구조가 아니다. 경계의 전체 비영성 때문에 높이 끝점 T도 안전하게 포함된다. 비자명한 영점이 원래 임계 띠 안에 있다는 표준 정리와 결합한 유한 높이 결론의 범위도 [DLMF 25.10](https://dlmf.nist.gov/25.10)과 일치한다.

## 4. 정확도·관련 FLINT 비교·실패 이력

감김수, root enclosure, 양끝 Hardy 함수값, FLINT 비교 영점에서 실제 dyadic 폭을 확인한다. 192라는 precision 숫자만으로 정확도 충족을 선언하지 않는다. 저장된 T=20·30 감김수 구간과 부호 구간의 폭도 이 검토에서 정확한 유리수로 다시 확인했다. 낮은 정밀도 negative control은 `WINDING_WIDTH`로 실패한다.

`zeta_nzeros`와 `zeta_zeros`는 관련 Gram/Turing 계통이므로 둘을 독립적인 증명 두 개로 세지 않는다. 새 contour 알고리즘은 그 두 함수를 사용해 총수를 정하지 않으므로 별도 counting 알고리즘이라는 표현은 맞다. 다만 같은 FLINT 산술과 ζ 평가기를 공유한다는 제한을 유지한다.

첫 attempt1의 실패는 negative fixture에서 `arb("1 +/- 1/8")`를 사용한 API 문자열 오류였다. 실제 첫 두 높이 기록과 수학 본체가 최종 기록과 동일하다는 점을 대조했다. 이 첫 11/12 실행을 성공으로 세지 않았고, fixture 수정 뒤 attempt2의 12/12와 관측 exit 0을 별도로 사용했다.

## 5. 최종 범위

이 검토는 실제 두 유한 높이의 수치 전제와 서술한 논증을 연결한다. 무한 높이의 RH, FLINT와 독립적인 산술 라이브러리 검증, 새로운 형식 kernel proof, P7 전체 완료를 의미하지 않는다. 저장된 certificate가 새로운 계산을 자동 인증한다고 보지 않으며 재실행은 원래 constructor를 다시 호출해야 한다. 본체의 최종 scope flags가 이 제한을 유지하는 것을 확인했다.
