# 실제617375 역수와 엄격한 부호 전달의 독립 검토

fresh run38728776386의 원본 header/fixed 해시에 묶인 20-node 완전 cone을
독립적으로 대조했다. 실제 분모617372는

```
R = C12EnvelopeR = exp(sourceEnvelopeS^256) > 1,
kappa = directionalMarginKappa = R^(-10) > 0,
B = sqrt(1+(2/kappa)^2) > 1,
617372 = -max(-B/R^6,-B/R^6,-B R^10,-B R^10).
```

양쪽 후보가 유한하고 엄격히 음수이므로 유한 maximum도 엄격히 음수다.
따라서 분모는 엄격히 양수다. 더욱이 R>1이므로 R^-6<R^10이고
분모는 정확히 B/R^6>R^-6>0이다. 실제 역수617375는 R^6/B로 유한하며
양수다. 원래 maximum을 생산자에서 다른 식으로 바꾸지 않고, 동일 식의
부호와 수학적 항등식만 증명했다. 거대한 실제 숫자를 십진수로 만들지 않는다.

이전 enclosure의 hi=0은 실제 값이 0이라는 뜻이 아니었다. 각 후보가
0에 가까울 수 있지만 여전히 음수라는 사실을 `strict_negative`로 보존하면
이 실제 분모의 비소멸을 잃지 않는다. 곱은 두 엄격한 부호의 표를 따르고,
유한 maximum은 **모든** 인자가 엄격히 음수일 때만 엄격히 음수다.
0 또는 부호 미정의 비양수 인자가 하나라도 있으면 이 결론을 내리지 않는다.
역수는 엄격한 양/음의 부호가 있을 때만 허용한다. 덧셈, 양의 정수 거듭제곱,
음수 역수, log의 부호와 양의 sqrt의 규칙도 보수적 enclosure와 일치했다.

독립 검증기 `peer_background_strict_sign_verify.py`는 실제20-node와 고정
원본 R/kappa 표현식을 정확히 대조한다. 60개의 서로 다른 enclosure에
대해 실제 유리수 값들을 별도로 열거하여 115,784개의 덧셈·곱·maximum·
역수·정수 거듭제곱 상계 및 엄격 부호 명제를 검사했다. 실제 maximum에
0을 추가하는 반례 변형은 반드시 거부된다. 원래 배경 검증의 25개 단위
검증도 독립적으로 재실행해 통과했다.

이 검토는 이 실제 역수의 정의역 장애와 부호 전달 구현을 승인한다.
변경된 전체 배경 gate는 다음 fresh 실행으로 확인해야 한다. 이 검토만으로
원본 배경26행, 전체 g의 J 정칙성 또는 PDE를 완료로 변경하지 않는다.
