# 원래 양의 profile 수치 구간: ROOT 독립 검토

검토 기준 커밋은 `6a3e71a884e6faebe808fd67fd0274304a7f45e4`다. 이 문서는
구현자가 작성한 증명 설명과 별개로 원래 매개변수 정의, 지수 높이,
부호에 따른 구간 방향, 양의 잔여항, 실제 실행 기록을 대조한다.

## 판정과 정확도 범위

현재 구현의 **15개 양의 수치 중첩 지수 구간**에 수학적 반례나 원래
profile의 치환을 발견하지 못했다. 24개 원래 정의의 문자 그대로의
대조와 directed 유리수 로그 계산은 이 판정의 서로 다른 부분이다.
끝점은 유리수 상수 및 `exp`/`neg`로 닫혀 있고 실제 양의 실수다.

정확도는 각 행에 명시한 반복 로그 좌표의 폭이다. 이는 원래 (h),
(C), (R_{\rm env})의 상대 오차 보장이 아니다. 실제 공통 selector의
norm, 선택한 정수 band, palette fractional part 및 target (\tau)는
이 모듈의 결과에 포함되지 않는다. 따라서 이 검토는 전체 G-NUM이나
M2 완료를 승인하지 않는다.

## 원래 정의와 지수 높이의 재계산

원래 (M=1048576), (T=e^M+10), (h=e^{-8002T}>0)를 유지한다.
코드의 상수를 독립적으로 정수 계산하면

\[
4+8(8002)=64020,\quad 200(64020)=12804000,
\quad 64(64020)+8(8002)=4161296.
\]

따라서 (Q_{\rm prof}=2^{260}2000^2e^{64020T})는 높이 2,
선택한 (C)와 (C_{\rm axis})는 높이 3,
(R_{\rm env}=\exp(C^{25600000}))는 높이 4의 지수 끝점을 갖는다.
여기서 (Q_{\rm prof})를 물리 pulse의 (Q=2^{-\ell})와 같다고 쓰지 않는다.

(a=260\log2+2\log2000<276), (L=64020T+a), (Y=200L)라 두면

\[
\log C=e^Y+10\log(1+e^{3Y/2}).
\]

추가항은 양수이고 그 비율은 (Y\ge16)에서
((15Y+10)e^{-Y}<1)이다. (e^Y\ge Y^3/6)와
(16^3>6(15\cdot16+10))을 확인했고, 두 다항식의 차는 이후
단조 증가한다. 따라서 (\log\log C=Y+\xi), (0<\xi<1)로
양의 추가항을 보존할 수 있다. 최종 로그에서의 보정은
(11e^{-M})보다 작다.

축 상수의 원래 `+1`도 남아 있다. 그 양의 계수 로그는
(64\cdot276+6+16) 아래이며, 지수 계수 (4161296)보다 작다.
동일한 최종 반복 로그 추정이 적용된다.

## 추가 곱·거듭제곱·올림의 오차

(x=\log\log C=Y+\xi)라 하면 코드에 나타난 C/Renv 변환의
최종 좌표는 (\log(x+d)), (0\le d<19)로 제어된다.
(\log100000<12), (\log25600000<18) 및 원래 양의 추가항을
대조했다. `1+ceil(Renv^50)`에 대해서는 실제 값과 (Renv^{50})의
차이가 2 이하라는 사실을 사용하며 올림을 미분하거나 버리지 않는다.

특히 (X_R=110C^{10}P_*^{10})에서는

\[
\log X_R=10\log C+20T+\log110,
\]

\[
\log\log X_R=x+\log10+
\log\left(1+\frac{20T+\log110}{10e^x}\right).
\]

마지막 비율은 1보다 작다. 따라서 이 경우의 (d)는
(\log10+\log2<4)이고 공통 19 여유 안에 있다. 이는 원래
(P_*^{10})이나 110을 생략한 근사가 아니다.

모든 행의 최종 보정은 (32e^{-M}<32\,2^{-M}<2^{-4096})이다.
구현은 이 **양의** 유리수 여유를 directed arithmetic으로 더한다.
아주 작은 원래 (h)를 binary64의 0으로 바꾸지 않는다.

## 구간 방향과 실행 대조

작은 양수의 seed (a\le b)에 대해 (e^{-e^b}\le h\le e^{-e^a})다.
`small:true`에서 seed 순서를 뒤집는 것을 확인했다. 큰 양수의
끝점은 증가 방향을 유지한다. regular (\sqrt2)의 유리수 양 끝은
각각 제곱하여 2의 아래·위를 둘러싼다는 별도 검증도 통과했다.

독립 실행은 Node 종료 코드 **0**, spec reporter의 **7/7 통과**,
실패·취소·건너뜀 각각 0을 실제로 관측했다. 실행 전후 아래 4개
파일의 SHA256은 같았다. 첫 Python wrapper는 Node v24의 spec
출력을 TAP으로 예상하여 결과 개수 파싱에서 종료 코드 1을 냈다.
Node의 수학 검증 실패가 아니다. 원래 로그와 첫 receipt를 보존하고,
별도 `independent-root-kernel-attempt1-parser-correction.json`에
실제 spec 줄을 파싱한 근거를 남겼다. 테스트를 재실행하지 않았다.

이 경량 실행에서 실제 전체 배경장 또는 물리 pulse source를 다시
생성했다고 세지 않는다. 새 Lean kernel 실행 또는 M3 진행도
이 문서의 판정에 포함되지 않는다.
